# Сайт «По полочкам»

Сайт-библиотека роликов на [Astro](https://astro.build). Страницы собираются из файла
`src/data/articles.json`, который выгружает бот командой `/articles`. Сервер с базой не нужен:
после сборки получается папка с готовыми HTML-файлами, её можно положить на любой хостинг.

## Что уже есть

| Требование БТ | Где на сайте |
|---|---|
| FR-L01 Страница на каждый вопрос, адрес и заголовок — сам вопрос | `/<slug>/` |
| FR-L02 Ролик на странице | плеер VK Видео / Rutube / OK / YouTube, ссылки на остальные площадки |
| FR-L03 Текст на один экран | блок «Суть / Что сделать / Срок» (поле `summary`) и текст статьи |
| FR-L04 Факты со ссылками и «Актуально на …» | раздел «Ключевые факты и источники» |
| FR-L05 «Правило изменилось» | плашка сверху (поля `rule_changed`, `replaced_by`) |
| FR-L06 Похожие вопросы с той же полки | внизу страницы |
| FR-L07 «Поделиться» и короткая ссылка | кнопки на странице, короткие ссылки `/s/<номер>/` |

| FR-L13 Подписка, FR-L15 голосование за темы | пока страница `/predlozhit-temu/` со ссылкой; нужен сервер — следующий этап |

## SEO

Что сайт делает сам:

- **Адрес и заголовок — сам вопрос** (транслит), один `h1` на странице, подзаголовки `h2` из текста статьи.
- **Title и description** у каждой страницы свои; description — 120–160 знаков из «Сути» или первого абзаца.
- **Канонические адреса** со слешем на конце. Если вышла новая версия ролика (`replaced_by`), старая страница
  указывает каноническим адресом на новую и пропадает из sitemap. Короткие ссылки `/s/…` — `noindex` и закрыты в robots.
- **Разметка schema.org (JSON-LD)**: Article (даты, издатель, источники), FAQPage (вопрос — ответ),
  VideoObject (плеер VK, обложка, дата), BreadcrumbList, ItemList на списках, WebSite с поиском, Organization.
- **Обложки 1200×630** для каждого вопроса рисуются при сборке (`/og/<slug>.png`): для VK, Telegram, Яндекса.
  Вертикальная `/og/<slug>-v.png` — заставка плеера.
- **Скорость**: страницы — готовый HTML без фреймворка, шрифты свои (не Google Fonts), плеер VK грузится
  только по нажатию на заставку.
- `sitemap.xml` с датами изменений, `robots.txt`, `rss.xml`, `/voprosy/` — все вопросы одним списком, favicon для выдачи Яндекса.
- **IndexNow**: после выкладки бот сообщает Яндексу о новых и изменённых страницах (`INDEXNOW_KEY` в `.env` бота).

Что сделать вам один раз после запуска домена:

1. **Яндекс Вебмастер** (webmaster.yandex.ru): добавить сайт, подтвердить мета-тегом — код в `YANDEX_VERIFICATION`
   (переменная окружения при сборке) или в `src/config.ts`. Там же: «Индексирование → Файлы Sitemap» — добавить
   `https://<домен>/sitemap.xml`; «Регион» — Россия; «Быстрые ссылки» и «Товары и цены» не нужны.
2. **Яндекс Метрика**: создать счётчик, номер — в `METRIKA_ID`. Поведенческие факторы для Яндекса важны.
3. **nginx**: пример в `deploy/nginx.conf` — HTTPS, один адрес без www, слеш на конце через 301, сжатие, кэш, 404.
4. По желанию **Google Search Console** — код в `GOOGLE_VERIFICATION`.

## Как поменять настройки

Всё в одном файле `src/config.ts`: название, стиль оформления (`theme`), полки, ссылки на каналы,
куда ведёт кнопка «Предложить тему». Стили: `a` «Справочник», `b` «Полки», `c` «Тёплый»,
`cb` «Тёплый» с тёмно-коричневой шапкой и цветными полками,
`g` «Тёплый с коричневым» — фирменный стиль Г, сейчас включён он.

Адрес сайта (домен) в код не зашит. Он задаётся при сборке переменной `SITE_URL`.
На GitHub: репозиторий → Settings → Secrets and variables → Actions → вкладка Variables →
New repository variable, имя `SITE_URL`, значение например `https://popolochkam.ru`.

## Как обновлять сайт

Сайт собирает и выкладывает сам бот, на той машине, где он работает (GitHub не нужен):

1. Установите Node.js 22 на машину с ботом.
2. В `.env` бота задайте `SITE_URL` (адрес сайта) и `SITE_DEPLOY_CMD` — команду, которая
   копирует готовую папку на хостинг. Путь к папке бот передаёт в переменной `SITE_DIST`, например:
   `rsync -az --delete "$SITE_DIST/" user@host:/var/www/popolochkam/`
3. Команда боту `/site` — бот запишет статьи из базы в `src/data/articles.bot.json` (файл не в git;
   пока его нет, сайт показывает примеры из `src/data/articles.json`), выполнит
   `npm run build` и затем `SITE_DEPLOY_CMD`. С `SITE_AUTO_BUILD=true` бот делает это сам после каждой новой статьи.

Вручную: `npm run build` в папке `site` и загрузите содержимое `site/dist` на хостинг
(любой статический хостинг или nginx). В `.github/workflows/site.yml` есть сборка на GitHub — её можно удалить,
если код переедет в другое место.

## Ролик на странице

Ролик стоит сверху, статья под ним. По умолчанию встраивается плеер площадки по ссылке из публикации,
в порядке: VK Видео, Rutube, Одноклассники, YouTube. Если в `.env` бота `SITE_OWN_VIDEO=true`, бот кладёт
на сайт свой mp4 (720p) и обложку (поля `video_file`, `poster`), и показывается обычный HTML5-плеер.

## Поля статьи в articles.json

Бот уже отдаёт: `id`, `title`, `slug`, `body`, `videos`, `sources`, `actual_date`, `updated_at`.
Сайт заранее понимает и эти поля (бот начнёт их отдавать по FR-47):

- `shelf` — полка: id из `config.ts` (`nalogi`, `ip`, `vyplaty`, `zhilyo`, `zemlya`, `zhkh`, `shtrafy`, `finansy`, `krym`) или её название. Без полки статья попадает в «Разное».
- `audience` — для кого: список из `people`, `ip`, `selfemployed`, `business`.
- `summary` — `{ "essence": "…", "todo": "…", "deadline": "…" }`.
- `replaced_by` — slug новой версии, если правило изменилось; `rule_changed: true` — если новой версии ещё нет.
- `published_at` — дата первой публикации.

Все эти поля необязательные. Пока ни у одной статьи нет полки, сайт не показывает полки
(ни в меню, ни на главной), а «Похожие вопросы» превращаются в «Другие вопросы».
Фильтр «для кого» появляется, только если хотя бы у одной статьи заполнено `audience`.

В `src/data/articles.json` лежат три статьи-примера. Как только бот создаст `articles.bot.json`, сайт берёт статьи из него.
