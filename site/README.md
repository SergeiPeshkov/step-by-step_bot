# Сайт «По полочкам»

Сайт-библиотека роликов на [Astro](https://astro.build). Страницы собираются из файла
`src/data/articles.json`, который выгружает бот командой `/articles`. Сервер с базой не нужен:
после сборки получается папка с готовыми HTML-файлами, её можно положить на любой хостинг.

## Что уже есть

| Требование БТ | Где на сайте |
|---|---|
| FR-L01 Страница на каждый вопрос, адрес и заголовок — сам вопрос | `/<slug>/` |
| FR-L02 Ролик на странице | плеер VK Видео / Rutube / OK / YouTube, ссылки на остальные площадки |
| FR-L03 Текст на один экран | блок «Суть / Что сделать / Срок» (поле `summary`) и текст статьи |
| FR-L04 Факты со ссылками и «Актуально на …» | раздел «Ключевые факты и источники» |
| FR-L05 «Правило изменилось» | плашка сверху (поля `rule_changed`, `replaced_by`) |
| FR-L06 Похожие вопросы с той же полки | внизу страницы |
| FR-L07 «Поделиться» и короткая ссылка | кнопки на странице, короткие ссылки `/s/<номер>/` |
| FR-L08 Страница создаётся из утверждённого ролика | из `articles.json` при сборке |
| FR-L09 Полки | `/polka/` и `/polka/<полка>/`, список в `src/config.ts` |
| FR-L10 Фильтр «для кого» | кнопки над карточками |
| FR-L11 Поиск «опишите свой вопрос» | `/poisk/` — поиск по словам; ИИ можно добавить позже |
| FR-L12 «Что изменилось» | `/izmeneniya/` |
| FR-L13 Подписка, FR-L15 голосование за темы | пока страница `/predlozhit-temu/` со ссылкой; нужен сервер — следующий этап |
| FR-L14 Без регистрации | регистрации нет |
| Яндекс | `sitemap.xml`, `robots.txt`, разметка schema.org |

## Как поменять настройки

Всё в одном файле `src/config.ts`: название, стиль оформления (`theme`), полки, ссылки на каналы,
куда ведёт кнопка «Предложить тему». Стили: `a` «Справочник», `b` «Полки», `c` «Тёплый»,
`cb` «Тёплый» с тёмно-коричневой шапкой и цветными полками (сейчас включён он).

Адрес сайта (домен) в код не зашит. Он задаётся при сборке переменной `SITE_URL`.
На GitHub: репозиторий → Settings → Secrets and variables → Actions → вкладка Variables →
New repository variable, имя `SITE_URL`, значение например `https://popolochkam.ru`.

## Как обновить статьи (через сайт GitHub, без программ)

1. В Telegram отправьте боту `/articles` — он пришлёт файл `articles.json`.
2. На GitHub откройте репозиторий → папку `site/src/data/`.
3. Нажмите **Add file → Upload files**, перетащите `articles.json`, внизу нажмите **Commit changes**.
4. GitHub сам соберёт сайт (вкладка **Actions**, запуск «Сайт», 1–2 минуты).
5. Готовый сайт: Actions → последний зелёный запуск «Сайт» → внизу **Artifacts → site**.
   Это zip-архив, его содержимое загружается на хостинг в папку сайта.

Позже это можно автоматизировать: бот сам кладёт файл, а GitHub сам выкладывает сайт на хостинг.

## Поля статьи в articles.json

Бот уже отдаёт: `id`, `title`, `slug`, `body`, `videos`, `sources`, `actual_date`, `updated_at`.
Сайт заранее понимает и эти поля (бот начнёт их отдавать по FR-47):

- `shelf` — полка: id из `config.ts` (`nalogi`, `ip`, `vyplaty`, `zhilyo`, `zemlya`, `zhkh`, `shtrafy`, `finansy`, `krym`) или её название. Без полки статья попадает в «Разное».
- `audience` — для кого: список из `people`, `ip`, `selfemployed`, `business`.
- `summary` — `{ "essence": "…", "todo": "…", "deadline": "…" }`.
- `replaced_by` — slug новой версии, если правило изменилось; `rule_changed: true` — если новой версии ещё нет.
- `published_at` — дата первой публикации.

Все эти поля необязательные. Пока ни у одной статьи нет полки, сайт не показывает полки
(ни в меню, ни на главной), а «Похожие вопросы» превращаются в «Другие вопросы».
Фильтр «для кого» появляется, только если хотя бы у одной статьи заполнено `audience`.

Сейчас в `src/data/articles.json` лежат три статьи-примера. Их заменит первая выгрузка из бота.
